# Multithreading in Java

### Uniprocessing
In uniprocessing, only one process can occupy the memory at a time. The major drawbacks are:
1. Memory wastage
2. Resource wastage
3. CPU idle time

### Multitasking
To avoid the problems of uniprocessing, multitasking was introduced. In multitasking, multiple tasks can concurrently work with CPU, completing tasks more efficiently.

Multitasking is divided into two categories:
1. **Process-based Multitasking**: CPU switches from one subtask (thread) of one process to another subtask of another process
2. **Thread-based Multitasking**: CPU switches from one subtask (thread) to another subtask within the same process

## Threads in Java

### What is a Thread?
A thread is a lightweight process and the basic unit of CPU execution that can run concurrently with other threads within the same context (process).

- Known for independent execution
- Main purpose is to boost execution sequence
- Threads can run simultaneously, completing tasks faster

### Main Thread in Java
- JVM internally creates a thread called "main thread" whenever we define a main method
- `Thread` is a predefined class in `java.lang` package
- `currentThread()` is a static method that returns the currently executing thread
- `getName()` method returns the thread's name

```java
public class MainThread {
    public static void main(String[] args) {
        Thread t1 = Thread.currentThread();
        System.out.println(t1.getName());
        
        // OR
        System.out.println(Thread.currentThread().getName());
        
        // OR
        String name = Thread.currentThread().getName();
        System.out.println("Current thread name is: " + name);
    }
}
```

## Creating User-Defined Threads in Java

There are two ways to create a user-defined thread:
1. By extending `java.lang.Thread` class
2. By implementing `java.lang.Runnable` interface

### 1. Extending Thread Class

```java
class Test extends Thread {
    @Override
    public void run() {
        System.out.println("Child Thread is running");
    }
}

public class UserThread {
    public static void main(String[] args) {
        System.out.println("Main thread started.");
        
        Test t1 = new Test();
        t1.start();
        
        System.out.println("main thread ended.");
    }
}
```

```java

    }

```

## Important Thread Methods

### `start()` Method
- A synchronized method of Thread class
- Performs two tasks:
  1. Makes a request to the operating system to assign a new thread for concurrent execution
  2. Internally invokes the `run()` method as part of a separate stack
- JVM creates a separate runtime stack for each thread

### `isAlive()` Method
- Determines if a thread has started or not
- Returns `false` if called before `start()`
- Returns `true` if called after `start()`
- Cannot restart a thread in Java; attempting to do so will throw `java.lang.IllegalThreadStateException`

```java
class Foo extends Thread {
    @Override
    public void run() {
        System.out.println("Child thread is running...");
    }
}

public class IsAlive {
    public static void main(String[] args) {
        System.out.println("Main Thread is started..");
        Foo f = new Foo();
        System.out.println("Thread has not started yet so: " + f.isAlive());
        
        f.start(); // new Thread has created
        
        System.out.println("Thread has started so: " + f.isAlive());
        // f.start();   // Will throw java.lang.IllegalThreadStateException
    }
}
```

### `sleep()` Method
- Puts a thread into temporary waiting state
- Static method of Thread class
- Throws checked exception `InterruptedException`
- Usage: `Thread.sleep(1000);` // Thread will wait for 1 second

```java
class Sleep extends Thread {
    @Override
    public void run() {
        for(int i=1; i<=10; i++) {
            System.out.println("i value is: " + i);
            try {
                Thread.sleep(1000);
            } catch(InterruptedException e) {
                System.err.println("Thread is Interrupted " + e);
            }
        }
    }
}

public class SleepDemo {
    public static void main(String[] args) {
        Sleep s = new Sleep();
        s.start();
    }
}
```

### `join()` Method
- Puts one thread into waiting mode until another thread finishes execution
- The current thread waits until the thread on which `join()` is called reaches its dead state
- Throws checked exception `InterruptedException`
- Instance method called with Thread object reference

```java
class Join extends Thread {
    @Override
    public void run() {
        for(int i=1; i<=5; i++) {
            try {
                Thread.sleep(1000);
            } catch(Exception e) {
                e.printStackTrace();
            }
            System.out.println("i value is: " + i);
        }
    }
}

public class JoinDemo {
    public static void main(String[] args) throws InterruptedException {
        System.out.println("Main thread started....");
        
        Join j1 = new Join();
        Join j2 = new Join();
        Join j3 = new Join();
        
        j1.start();
        j1.join(); // Main thread waits for j1 to complete
        
        j2.start();
        j3.start();
        
        System.out.println("Main thread ended....");
    }
}
```

## Thread Life Cycle in Java

A thread passes through 5 states during its lifecycle:

![Multithreading](https://media.licdn.com/dms/image/v2/D5612AQE2GE-5x02rcw/article-cover_image-shrink_720_1280/article-cover_image-shrink_720_1280/0/1691427612573?e=2147483647&v=beta&t=qUc8owAv8f6kurDR9sksZlZfAXxxYtAlodqwQqbRiGs "Mul")

1. **NEW State (Born state)**
   - Thread instance created but not started yet

2. **RUNNABLE state (Ready to Run state)**
   - After calling `start()` method
   - Thread is ready to run but waiting for Thread Scheduler to select it

3. **RUNNING state**
   - Thread is executing its `run()` method
   - Can move to waiting state via `wait()`, `join()`, or `sleep()`
   - Can move to runnable state via `yield()`

4. **WAITING/BLOCKED state**
   - Thread is waiting for its time period to complete
   - After completion, re-enters runnable state

5. **EXIT/DEAD state**
   - Thread has completed its `run()` method execution
   - Cannot restart a dead thread

> **Important**: When a thread wakes up after `sleep()`, it doesn't go directly to the RUNNING state. Instead, it re-enters the RUNNABLE state and waits for the Thread Scheduler to select it.

## Problems with Multithreading

### Race Condition/Data Race
- All threads try to access a resource simultaneously, leading to corrupted results
- Multithreading works well for read operations on non-updatable data
- May produce incorrect results with updatable/modifiable data

### Example: Banking Application Problem
```java
class Client {
    int availableBalance = 20000;
    int withdrawBalance;
    
    public Client(int withdrawBalance) {
        this.withdrawBalance = withdrawBalance;
    }
}

public class BankingApplication {
    public static void main(String[] args) {
        Client c1 = new Client(20000);
        
        Runnable r1 = () -> {
            String name = null;
            if(c1.withdrawBalance <= c1.availableBalance) {
                name = Thread.currentThread().getName();
                System.out.println(c1.withdrawBalance + " amount withdraw by: " + name);
                c1.availableBalance = c1.availableBalance - c1.withdrawBalance;
            } else {
                name = Thread.currentThread().getName();
                System.err.println("Sorry " + name + " insufficient balance");
            }
        };
        
        Thread t1 = new Thread(r1, "Virat");
        Thread t2 = new Thread(r1, "Rohit");
        
        t1.start(); 
        t2.start();
    }
}
```

### Example: Railway Reservation Problem
```java
class Customer implements Runnable {
    private int availableSeat = 1;
    private int wantedSeat;
    
    public Customer(int wantedSeat) {

    }
}
```

## Synchronization in Java

Synchronization is a mechanism that controls access to shared resources by multiple threads to avoid data inconsistency.

### Need for Synchronization

As we saw in our previous examples (Banking and Railway Reservation), when multiple threads access shared resources simultaneously, they can cause data corruption or race conditions.

Problems without synchronization:
1. Data inconsistency
2. Race conditions
3. Thread interference
4. Memory consistency errors

### Types of Synchronization

#### 1. Process Synchronization
Controls access to shared resources between multiple processes.

#### 2. Thread Synchronization
Controls access to shared resources between multiple threads. There are two types:

##### a) Mutual Exclusive
- Ensures that only one thread can access the resource at a time
- Types:
  - Synchronized method
  - Synchronized block
  - Static synchronization
  - Lock interface

##### b) Cooperation (Inter-thread communication)
- Allows communication between threads
- Implemented using `wait()`, `notify()`, and `notifyAll()` methods

### Synchronized Methods

To create a synchronized method, add the `synchronized` keyword to the method declaration.

```java
public synchronized void withdraw(int amount) {
    // method body
}
```

Example - Fixed Banking Application:

```java
class Client {
    private int availableBalance = 20000;
    
    public synchronized void withdraw(int withdrawAmount) {
        String name = Thread.currentThread().getName();
        if(withdrawAmount <= availableBalance) {
            System.out.println(withdrawAmount + " amount withdrawn by: " + name);
            availableBalance = availableBalance - withdrawAmount;
            System.out.println("Remaining balance: " + availableBalance);
        } else {
            System.err.println("Sorry " + name + ", insufficient balance!");
        }
    }
}

public class SynchronizedBankingDemo {
    public static void main(String[] args) {
        Client c1 = new Client();
        
        Runnable r1 = () -> {
            c1.withdraw(15000);
        };
        
        Thread t1 = new Thread(r1, "Virat");
        Thread t2 = new Thread(r1, "Rohit");
        
        t1.start(); 
        t2.start();
    }
}
```

### Synchronized Block

If we want to synchronize only a specific part of a method, we can use synchronized block.

Syntax:
```java
synchronized(object_reference) {
    // synchronized code block
}
```

Example:
```java
class Customer implements Runnable {
    private int availableSeat = 1;
    
    @Override
    public void run() {
        String name = Thread.currentThread().getName();
        System.out.println(name + " entered booking section");

                System.out.println("Seat reserved for " + name);
                availableSeat--;
            } else {
                System.err.println("Sorry " + name + ", no seats available");
            }
        }
        
        System.out.println(name + " left booking section");
    }
}

public class SynchronizedBlockDemo {
    public static void main(String[] args) {
        Customer c1 = new Customer();
        
        Thread t1 = new Thread(c1, "Passenger1");
        Thread t2 = new Thread(c1, "Passenger2");
        
        t1.start();
        t2.start();
    }
}
```

### Lock Interface

Java provides a more flexible locking mechanism through the `Lock` interface.

```java
import java.util.concurrent.locks.Lock;
import java.util.concurrent.locks.ReentrantLock;

class BankAccount {
    private double balance = 10000;
    private Lock lock = new ReentrantLock();
    
    public void withdraw(double amount) {
        lock.lock();
        try {
            if(balance >= amount) {
                balance -= amount;
                System.out.println("Withdrawal successful, remaining balance: " + balance);
            } else {
                System.out.println("Insufficient funds");
            }
        } finally {
            lock.unlock(); // Always release lock in finally block
        }
    }
}
```

### Inter-thread Communication

Used when one thread is dependent on another thread's completion.

Methods:
- `wait()`: Causes current thread to wait until another thread invokes `notify()` or `notifyAll()`
- `notify()`: Wakes up a single thread waiting on this object
- `notifyAll()`: Wakes up all threads waiting on this object

Example - Producer-Consumer Problem:
```java
class SharedResource {
    private int data;
    private boolean produced = false;
    
    public synchronized void produce(int value) {
        while(produced) {
            try {
                wait(); // Wait if item already produced
            } catch(InterruptedException e) {
                e.printStackTrace();
            }
        }
        
        data = value;
        System.out.println("Produced: " + data);
        produced = true;
        notify(); // Notify consumer
    }
    
    public synchronized int consume() {
        while(!produced) {
            try {
                wait(); // Wait if no item produced
            } catch(InterruptedException e) {
                e.printStackTrace();
            }
        }
        
        System.out.println("Consumed: " + data);
        produced = false;
        notify(); // Notify producer
        return data;
    }
}

class Producer implements Runnable {
    private SharedResource resource;
    
    public Producer(SharedResource resource) {
        this.resource = resource;
    }
    
    @Override
    public void run() {
        for(int i = 1; i <= 5; i++) {
            resource.produce(i);
            try {
                Thread.sleep(500);
            } catch(InterruptedException e) {
                e.printStackTrace();
            }
        }
    }
}

class Consumer implements Runnable {
    private SharedResource resource;
    
    public Consumer(SharedResource resource) {
        this.resource = resource;
    }
    
    @Override
    public void run() {
        for(int i = 1; i <= 5; i++) {
            resource.consume();
            try {
                Thread.sleep(500);
            } catch(InterruptedException e) {
                e.printStackTrace();
            }
        }
    }
}

public class ProducerConsumerDemo {
    public static void main(String[] args) {
        SharedResource resource = new SharedResource();
        
        Thread producer = new Thread(new Producer(resource));
        Thread consumer = new Thread(new Consumer(resource));
        
        producer.start();
        consumer.start();
    }
}
```

### Deadlock in Java

Deadlock occurs when two or more threads are blocked forever, each waiting for the other to release a lock.

Example of Deadlock:
```java
class DeadlockExample {
    private Object lock1 = new Object();
    private Object lock2 = new Object();
    
    public void method1() {
        synchronized(lock1) {
            System.out.println("Thread 1: Holding lock 1...");
            try {
                Thread.sleep(100);
            } catch(InterruptedException e) {
                e.printStackTrace();
            }
            System.out.println("Thread 1: Waiting for lock 2...");
            
            synchronized(lock2) {
                System.out.println("Thread 1: Holding lock 1 & 2...");
            }
        }
    }
    
    public void method2() {
        synchronized(lock2) {
            System.out.println("Thread 2: Holding lock 2...");
            try {
                Thread.sleep(100);
            } catch(InterruptedException e) {
                e.printStackTrace();
            }
            System.out.println("Thread 2: Waiting for lock 1...");
            
            synchronized(lock1) {
                System.out.println("Thread 2: Holding lock 1 & 2...");
            }
        }
    }
}

public class DeadlockDemo {
    public static void main(String[] args) {
        final DeadlockExample deadlock = new DeadlockExample();
        
        Thread t1 = new Thread(() -> {
            deadlock.method1();
        });
        
        Thread t2 = new Thread(() -> {
            deadlock.method2();
        });
        
        t1.start();
        t2.start();
    }
}
```

### How to Avoid Deadlock
1. Always acquire locks in the same order
2. Avoid nested locks
3. Use lock timeout (tryLock with timeout)
4. Detect deadlock and recover from it

### Thread Pool

Creating a new thread for each task can be inefficient. Thread pools maintain multiple threads waiting for tasks to be allocated.

```java
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

class Task implements Runnable {
    private String name;
    
    public Task(String name) {
        this.name = name;
    }
    
    @Override
    public void run() {
        System.out.println("Task " + name + " is running on " + 
            Thread.currentThread().getName());
        try {
            Thread.sleep(500);
        } catch(InterruptedException e) {
            e.printStackTrace();
        }
        System.out.println("Task " + name + " completed");
    }
}

public class ThreadPoolDemo {
    public static void main(String[] args) {
        // Create a fixed thread pool with 3 threads
        ExecutorService executor = Executors.newFixedThreadPool(3);
        
        // Submit 5 tasks
        for(int i = 1; i <= 5; i++) {
            executor.execute(new Task("Task-" + i));
        }
        
        // Shutdown the executor
        executor.shutdown();
    }
}
```
